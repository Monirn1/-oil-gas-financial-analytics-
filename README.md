# Corporate Financial Performance Analytics — Big Oil (BP, Chevron, Shell, ExxonMobil)

End-to-end financial analytics project comparing four major integrated oil & gas companies — **BP, Chevron (CVX), Shell (SHEL), and ExxonMobil (XOM)** — across fiscal years 2022-2025. Built with Python/pandas, culminating in a validated KPI framework, a benchmarking and scoring system, and a statistical deep-dive into what actually drives return on equity across the panel.

## Why this project

Most ratio-analysis projects stop at calculating margins and leverage ratios. This one goes a step further: it uses correlation analysis, OLS regression, DuPont decomposition, and PCA/clustering to explain *why* the companies differ, not just *that* they differ — including catching a real data-quality bug (inconsistent field naming between US GAAP and IFRS filers) and correcting a misleading conclusion a simple correlation would have produced.

## Key finding

BP's persistently weak ROE (2022-2025) is driven almost entirely by a **collapse in profit margin**, not by its leverage. In fact, once margin is controlled for, BP's above-sector leverage is shown to be a return *amplifier* — the same mechanism that would boost its ROE sharply if margins recovered. A simple correlation between leverage and ROE gets the direction of this relationship backwards; only the regression and DuPont decomposition together reveal the true mechanism. See [`reports/ROE_Drivers_Analysis.docx`](reports/ROE_Drivers_Analysis.docx) for the full write-up.

## What's in the analysis

**1. Data pipeline & KPI framework** (`notebooks/Oil_and_Gas_Clean_Pipeline.ipynb`)
- Standardizes income statement, balance sheet, and cash flow data across all 4 companies (2022-2025)
- Resolves a real data-quality issue: BP and Shell (IFRS filers) report receivables under "Accounts Receivable," while Chevron and ExxonMobil (US GAAP) use "Receivables" — standardized into a single field with full source lineage (`Receivables_Source` column)
- Builds a complete KPI framework across 7 categories (~27 indicators): profitability, liquidity, leverage, interest coverage, returns (incl. ROIC), efficiency, and cash flow quality
- Exports a 13-sheet Excel workbook ready for Power BI import

**2. Benchmarking & scoring**
- Cross-sectional 2025 benchmarking table across 11 headline ratios
- A composite, equal-weighted financial health score (5 categories: profitability, liquidity, financial risk, cash generation, growth)
- Oil & gas sector-specific volatility analysis (coefficient of variation on Revenue/EBITDA across the full cycle) — reveals that Shell, not BP, is actually the most volatile company on top-line metrics; BP's instability is concentrated below the operating line

**3. Statistical deep-dive** (`reports/ROE_Drivers_Analysis.docx`)
- **Correlation matrix** across 11 core ratios, pooled across the panel
- **OLS regression** of ROE on leverage, asset turnover, and margin (R² = 0.92) — isolates a sign flip on the leverage coefficient that a simple correlation misses entirely
- **DuPont decomposition** (ROE = Margin × Turnover × Equity Multiplier), validated to floating-point precision against reported ROE
- **PCA + K-Means clustering** on an 11-ratio feature set — formally confirms BP as a statistical outlier on a single "leverage vs. profitability" axis explaining 58.8% of variance

## Tech stack

`pandas` · `numpy` · `matplotlib` · `seaborn` · `scikit-learn` (StandardScaler, PCA, KMeans) · `statsmodels` (OLS) · `openpyxl`

## Data

Source data (`master_income_statement.csv`, `comparable_balance_sheet_2022_2025.csv`, `master_cash_flow.csv`) is built from company financial statements via the `yfinance` API. Place these three files in `data/processed/` before running the notebook — see the config cell at the top of `Oil_and_Gas_Clean_Pipeline.ipynb`.

## Running it

```bash
pip install pandas numpy matplotlib seaborn scikit-learn statsmodels openpyxl
jupyter notebook notebooks/Oil_and_Gas_Clean_Pipeline.ipynb
```

Update the `BASE_PATH` variable in the first code cell to point to your local `data/processed/` folder, then run all cells top to bottom.
